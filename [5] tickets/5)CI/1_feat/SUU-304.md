## Codex 메모
- `md_split.py` 공개 이름 4개
  - `ITEMS: list[tuple[str, list[str]]]`: 위 표 그대로. 폴더 이름과 장 제목(`## ` 뒤 글자)
  - `split(text: str, items=ITEMS) -> dict[str, str]`: 폴더 이름 → 항목 md 글. 순서는 `items` 순서
  - `write_items(full_path, items=ITEMS) -> list[Path]`: `full_path.parent.parent / 폴더 / f"{폴더}.md"`에 쓴다. 폴더가 없으면 만든다. UTF-8, LF(`newline=""`)
  - `main(argv: list[str], items=ITEMS) -> int`: 인자가 없으면 `1_full/1_Project_full.md`. 쓴 경로를 한 줄씩 출력하고 0. `ValueError`면 메시지를 출력하고 1, 아무 파일도 쓰지 않는다
  - `if __name__ == "__main__": sys.exit(main(sys.argv[1:]))`
- 자르는 규칙
  - 줄바꿈은 먼저 `\n`으로 맞춘다
  - 첫 줄(`# 제목`)은 버린다. 그 뒤부터 첫 `## ` 전까지가 표지
  - `## `로 시작하는 줄부터 다음 `## ` 줄 전까지가 장 하나. ```` ``` ```` 코드 블록 안의 줄은 장 경계가 아니다
  - 표지와 장은 앞뒤 빈 줄을 뗀다
  - 항목 글 = `"# Compliance AI · " + 폴더 이름에서 첫 "_" 앞 번호를 뗀 것`, 표지(첫 항목만, 비어 있지 않을 때), 장들을 `"\n\n"`으로 잇고 끝에 `"\n"` 하나
  - 제목에 "Compliance AI · "를 붙이는 이유: "TDD 개발 자동화"처럼 항목 이름과 장 이름이 같으면 `md_check`의 같은 제목 규칙에 걸린다
- 오류(`ValueError`): full의 장이 어느 항목에도 없거나, 두 번 이상 들어 있거나, 항목에 적힌 장이 full에 없을 때. 메시지에 문제 장 제목을 모두 넣는다
- `.claude/commands/report.md` 새 순서
  1. `python "[1] docs/4) workflow/report/md_split.py"` → 항목 md 5개를 full에서 다시 만든다. 1이면 메시지를 보여 주고 멈춘다
  2. `python "[1] docs/4) workflow/report/md_to_docx.py"` + md 7개 (summary, full, 항목 5개)
  3. 지금처럼 자동 수정·오류를 쉬운 한국어로 보여 주고, 성공하면 만든 .docx/.pdf 경로를 알려 준다
  - 인자가 없을 때 대상 설명도 새 경로 7개로 바꾼다
- 순서: `git mv` 두 개 → `md_split.py` 작성 → `python md_split.py`로 항목 md 생성·커밋 → 경로 수정
