# Compliance AI · 프로젝트 개요

"이 규정, 우리 공장에 적용되나요?"

미국 공장이 환경청(EPA)에 이렇게 물으면 답장까지 보통 101일. 4건 중 1건은 6개월이 걸립니다.

기다리는 동안에도 서류는 내야 합니다. 틀리면 서명한 책임자가 개인 책임을 지고, 갱신이 늦으면 공장이 멈춥니다. 대상 공장 10곳 중 3곳에 이미 위반 이력이 있습니다.

답은 957쪽 규정집 안에 이미 있습니다. 찾아 주는 사람이 없을 뿐입니다.

이 서비스는 그 자리에서 근거 조문을 찾아 줍니다.

17일 · 1인 개발 · PR 254개 · 정답 조문 적중률 69% → 93% (2026.09.10 ~ 09.26)

17일 중 5일은 코드 없이 문제 정의에만 썼습니다.

실제 사용자에게 묻기 위해 텍사스 공장 환경 담당자 45명에게 직접 콜드메일을 보냈습니다.

## 어필 포인트 5가지

> 5가지만 기억해 주세요.

① 만들고 끝내지 않았습니다. 실제 공장 담당자에게 직접 물었습니다.

텍사스 공장 45곳의 환경 담당자 45명에게 콜드메일을 보냈습니다.

목적은 두 가지입니다. 제가 정의한 문제가 현장에서도 맞는지 확인하고, 서비스 피드백을 받아 개선하는 것.

조항 번호를 어디서 찾는지, 한 달에 몇 시간 드는지, 개정을 어떻게 아는지, 무엇을 원하는지 묻고, 서비스를 직접 써 보고 틀린 곳을 알려 달라고 부탁했습니다.

② 실험을 통해 품질을 개선했습니다. 그냥 고른 것이 없습니다. 점수가 올라도 판단 하에 버렸습니다.

실험 9번, 채택 6, 기각 3. 임베더 2종, 리랭커 3종, LLM 2종, 하이브리드 가중치 132조합.

"좋다더라"로 고른 것이 없습니다. 전부 같은 평가셋 102건 위에서 전/후 숫자로 결정했습니다.

정답 조문을 고정으로 끼워 넣으면 +0.046이 올랐지만, 평가셋 정답을 미리 아는 꼼수라서 기각했습니다.

③ AI가 "적용됩니다"라고 말할 수 없게 만들었습니다.

AI가 판정하면 사람은 원문을 안 읽습니다. "참고용입니다" 문구로는 행동이 안 바뀝니다.

그래서 답변 JSON에서 판정 필드(`applies`)를 아예 없앴습니다. 시스템이 구조적으로 판정을 말할 수 없습니다.

대신 후보 조항 + 적용을 가르는 기준 + 확인 체크리스트를 주고, 모든 문장에 조문 근거를 답니다.

④ "이 코드 왜 이래요?"에 티켓 번호로 답할 수 있습니다.

Linear 티켓 286개(완료 258), 설계 파일 239개. 티켓 없이 시작한 기능이 하나도 없습니다.

티켓마다 왜 하는지·무엇을 바꾸는지·완료 기준을 설계 파일에 적습니다.

티켓 번호·브랜치·PR 제목·설계 파일 첫 줄이 서로 맞는지 CI가 검사하고, 설계 파일 없는 PR은 병합이 막힙니다.

혼자 만들었지만, 혼자만 아는 프로젝트가 아닙니다.

⑤ [TDD] AI의 "다 됐어요"를 믿지 않습니다. 테스트가 말하게 했습니다.

"완성"의 기준을 코드보다 먼저 테스트로 못 박았습니다.

Claude가 실패하는 테스트를 쓰고, Codex는 통과만 시킵니다. Codex는 테스트를 고칠 수 없습니다.

PR 254개마다 테스트 772개가 전부 다시 돌아, 옛 기능이 깨지면 병합 전에 잡힙니다.

검색·답변 품질도 같습니다. 실제 EPA 사례 102건 점수가 합격선 아래면 CI가 병합을 막습니다.

## 프로젝트 흐름

> 프로젝트를 혼자 수행했습니다. 혼자 했지만, 팀처럼 일하는 구조를 만들었습니다.

1. 문제 정의
2. 서비스 기획
3. TDD 개발 자동화 Flow 구축
4. CI/CD 파이프라인 구축
5. 데이터 파이프라인 구축
6. RAG 구축 및 검색/답변 품질 개선
7. 백엔드/프론트엔드 구축
8. UI 화면(웹사이트) 구축

서비스를 스스로 처음부터 끝까지 만들어보고 싶었습니다.

또한 1인 생산성을 높여보고 싶었습니다.

저는 방향을 정하고, 판단하고, 검토하는 일만 맡았습니다. 설계와 테스트 시나리오는 Claude Code, 구현은 Codex가 맡았습니다. 티켓, CI/CD, 배포, 알림은 자동화 했습니다.
